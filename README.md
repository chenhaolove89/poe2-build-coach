# PoE2 Build Coach

跟着 Build 走,不再翻文档。粘贴 Path of Building(PoE2)分享码,即刻得到这份 Build 的天赋目标点法、装备词缀清单与宝石配置 —— 纯离线桌面工具。

> 定位:PoE2 Build 的"跟随式教练"。别人给你 Build,我给你"现在第一步干什么"。
> 不重造 PoB2 的计算引擎,做它没做的执行层。

## 功能(M0)

- **PoB 分享码解析**:粘贴分享码 → 职业 / 升华 / 等级 / 天赋节点 / 技能组 / 装备全量提取
- **天赋树可视化**:0.5 版全树 Canvas 渲染(4900+ 节点),目标节点金色高亮
- 滚轮缩放 · 拖拽平移 · 双击复位 · 节点悬停显示词缀
- **异界天赋树**:573 个节点的终局天赋树,按机制子树分组、可规划点法;**按生态把树和地图表接起来**
- **分享码**:一个码带走服务器/赛季、天赋、异界天赋、装备;**格式层面不含登录凭证**
- **刷图统计**:读客户端日志算地图数/每图耗时/读图/死亡,产出与成本手动记账;**收益按区域码归到具体的图**,所以「哪张图值得刷」由你自己的实测回答
- 内置示例(从真实树生成,用于演示闭环)

## 服务器(设置页)

游戏分三个独立交易站,每个站的客户端只用自己那一种语言写物品文本,所以"粘贴的装备"必须和所在服的词缀模板对上才能查出价格:

| 选项 | 交易站 | 客户端语言 | 界面语言 | 匿名查询 |
| --- | --- | --- | --- | --- |
| 国际服 | `www.pathofexile.com/api/trade2` | English | 繁體 | 可以 |
| 国服 | `poe.game.qq.com/api/trade2` | 简体中文 | 简体 | **需登录** |
| 台服 | `pathofexile.tw/api/trade2` | 繁體中文 | 繁體 | 可以 |

**界面语言不单独设置,跟着服务器走。** 简体只在腾讯客户端存在;国际服客户端自带的是繁体而不是简体,所以国际服读繁体,而不是退回英文。这样只有一个开关,两者不会出现"用 A 服的模板匹配、界面上却显示 B 服字型"这种不一致。

- **国服**:数据接口(联赛、词缀模板、通货名)公开,但 `/search` 未登录会返回 401。在设置页点**关联登录**,会在一个独立窗口里打开腾讯官方登录页,用 QQ / 微信登录后自动取回会话 Cookie —— 和查价器常见的做法一致。账号密码只填在腾讯那一页,本工具不会接触;读到的只是登录后的 `POESESSID`,只存本机、只发给 `poe.game.qq.com`,仅用于只读查询。也可以手动粘贴(浏览器 F12 → Cookies)。不填也能做本地词缀匹配。
- **国服 / 台服是两套独立本地化**,不是简繁字型差异:同一件装备国服叫「引路石」、台服叫「換界石」,词缀语序也不同(`火焰抗性 #%` vs `#%火焰抗性`)。所以两套模板各自从本服接口抓取,而不是从国际服转换。

国际服为 Grinding Gear Games,国服为腾讯,台服为熱酷科技(接替 Garena 代理台港澳)。三者的交易站是各自独立的服务,联赛与物价互不相通。

## 架构

```
packages/core    纯 TS 业务核心(零环境依赖):PoB 码编解码/解析、天赋树几何、物品解析、查价查询构造、日志时间轴、简繁转换
packages/data    版本锁定的游戏数据包(tree.json 来自 PoB2 MIT;三服词缀模板、通货名、简繁对照表由 scripts 生成)
apps/desktop     Tauri 2 + Vue 3 桌面端
apps/website     GitHub Pages 下载页(纯静态)
```

核心纪律:**业务逻辑只进 core,两端复用**;未来网页版就是 core + Vue 视图。

## 开发

```bash
npm install
npm test                # core 单测(vitest)
npm run dev             # 桌面前端 vite dev(浏览器可直接调 UI)
npm run build           # core 类型检查 + 前端构建
```

桌面壳(Rust 未装时跳过,装好后即可运行):

```bash
# 安装 Rust:https://rustup.rs (需要 MSVC Build Tools)
cd apps/desktop
npm run tauri dev       # 开发运行
npm run tauri build     # 产出安装包(src-tauri/target/release/bundle/)
```

本地打包推荐用 `scripts\build-tauri.bat`,它在 `npm run tauri build` 外面套好了两件必须做的事:

- **构建前强制关掉正在运行的旧版本**。运行中的 `poe2-build-coach.exe` 会锁住 `target\release` 里的同名文件,cargo 链接时会直接失败(`failed to remove file ...: 拒绝访问 (os error 5)`)。脚本会等文件真的能删掉再继续,删不掉就报明确的错,而不是让 cargo 抛出难懂的 access denied。
- **构建成功后自动启动新版本**;只要安装包不启动,加 `--no-start`。

```bash
scripts\build-tauri.bat             # 关闭旧的 → 构建 → 启动新的
scripts\build-tauri.bat --no-start  # 只出安装包
```

CI 里不要用这个脚本(那里没有桌面、也没有实例要关);release 工作流直接调 `npx tauri build`。

## 数据来源与更新

- 天赋树:`packages/data/trees/0_5/tree.json`,取自 [PathOfBuilding-PoE2](https://github.com/PathOfBuildingCommunity/PathOfBuilding-PoE2)(MIT License)。
- 版本升级(如 12 月 1.0):下载新版 `TreeData/<ver>/tree.json` 放入 `packages/data/trees/<ver>/`,`apps/desktop/src/treeData.ts` 指向新版本即可。

### 天赋树美术

`packages/data/tree-art/` 里是节点图标、边框、连线、底部圆盘五张图集(约 1.4MB)以及两个派生索引,**取自 GGG 官方发布的 [poe2-skilltree-export](https://github.com/grindinggear/poe2-skilltree-export)**。官方开发者文档写明游戏内数据一概不提供、「唯一例外是天赋树」,所以这是第一方来源,不是逆向或第三方镜像。

**美术版权归 Grinding Gear Games 所有**,按 GGG 第三方工具政策在非商业粉丝工具中分发:本应用免费、不使用其素材制作其他游戏、不与游戏进程或游戏文件交互。界面上标注了版权,本仓库亦不主张对这些素材的任何权利。

`index.json` 把每个节点在树里的 `icon` 路径预先解析成图集矩形(图集是 0.5 倍存的,绘制尺寸由脚本换算好,升华节点另带底衬 Backing),`geometry.json` 是官方节点的绝对坐标与官方连线表 —— 渲染用的是这套坐标,因为它和美术同一坐标系,而 `packages/core` 里由 group+orbit 推算的坐标不是(同一个 group 在两边相差一个平移加缩放)。逻辑层不读坐标:`buildLevelingPlan` 只走连接图的 BFS,`resolveStartNode` 只读 `classesStart`。

**升华树在主树正中**:官方数据把 22 个升华簇摆在主树外约 17000 单位处,任何可用倍率下都在画面外;而主树是环形的、正中间空着(洞半径 1322),所以选中升华后被重投影到中心,并**等比缩放**到洞内 —— 22 个簇里有 13 个按原始尺寸放不进洞(最大的 Pathfinder 超 43%),等比缩放同时缩坐标与节点尺寸,保持簇内间距比例不变,因此不会互相压到。未选中的升华簇不绘制。

重新抓取(GGG 更新天赋树后):

```bash
node scripts/fetch-tree-assets.mjs --write
```

覆盖情况:显著天赋 1193/1193、核心天赋 33/33、升华 222/222、普通节点 3097/3466。未命中的 369 个是 `Mastery*` 占位图标,它们的专属美术在另一套 `mastery-effect` 图集里(约 640KB),本版本没有打包,所以这些节点画成空边框 —— 需要的话再加。

三个服的词缀模板与通货名重新抓取(联赛更新后跑一次):

```bash
node scripts/fetch-trade-data.mjs --write          # 全部三个服
node scripts/fetch-trade-data.mjs --realm cn --write   # 只更新国服
```

简繁对照表重新生成(需要网络拉取 OpenCC 词典,结果缓存于 `.tmp/opencc/`):

```bash
node scripts/build-zh-variant.mjs --write
```

两个脚本都会把语料里用不到的条目裁掉(词缀模板只留 explicit/implicit/fractured/crafted/enchant/rune/desecrated;简繁词组表只留本工具会显示的词),输出都是确定性的 —— 重跑不会产生无意义的 diff。

终局地图表重新生成(三个源抓取后缓存在 `.tmp/maps-src/`):

```bash
node scripts/build-maps.mjs              # 用缓存
node scripts/build-maps.mjs --refresh    # 重新抓 PoB2 / poe2wiki
```

POE2WAY 的评分与拓扑图是早先一次性采集的,以 `.tmp/maps-src/poe2way.json` 作为输入记录,不重复抓(它的 atlas 页是 RSC payload,不是 API)。地图表用真实日志审计:

```bash
node scripts/verify-map-codes.mjs "<安装目录>\logs\Client.txt"
```

它在日志里找 `Generating level … area …`,逐码报告能否对上表,并把每个码配上**客户端自己显示的中文名** —— 那是任何数据源都没有的东西(名字词典把 `Deforestation` 译作「伐林地」,而国服客户端显示「毁坏的林场」)。发现表外的 `Map*` 码会以非零退出。

## 刷图收益统计

读游戏的客户端日志(`<安装目录>\logs\Client.txt`,与 exe 同级)算时间轴:地图数、每图耗时、读图时间、非刷图时间、死亡、升级。**只读** —— 打开、seek、读,不写入也不锁写。日志路径优先向正在运行的游戏进程反查(国服由 WeGame 分发,装在它自己的目录树里,固定路径猜不到),失败再试 Program Files / Steam 库 / Documents,都不行就手动粘贴。

**产出必须手动记账,这不是没做完。** 客户端日志里没有任何掉落或拾取事件 —— 在真实国服日志上逐条数过关键词:物品、通货名、交易密语、剩余怪物全部 0 命中。Exiled-Exchange-2 的日志事件枚举是穷举的、里面没有 item 类事件;易刷的作者也直说他的记录器只知道你 Ctrl+C 查过的东西。所以掉了什么只能自己粘进来:游戏里 Ctrl+C 复制,粘到「本场收益」,查价填入或手填数量,记收入;门票同理记成本。查价与「查价」页共用官方限流(5/10s、15/60s、30/300s),超了会被拒而不是硬发。

三个容易踩的点:

- **PoE2 不发 `You have entered X.`**,那是 PoE1 的写法(网上不少正则表还带着它)。进区域要认的是 `Generating level N area "MapXxx"` 配 `[SCENE] Set Source [中文名]`。
- **区域代码是英文的,即使国服客户端**(`MapDeforestation`),中文名在同一条 `Set Source` 里。所以「这是不是地图」按代码的 `Map` 前缀判断,显示用中文名。
- **回到藏身处不会再生成区域**,因此没有代码行 —— 要按显示名记住上次判定的类型,否则每次回城都会被记成「其他」。

界面上的「净刷图 + 非刷图 + 读图 = 全程」是严格划分,三个数加起来必然等于会话时长(这是把数字摆上屏幕后第一件会被人核对的事)。日志被游戏重写(重装、手动删除)时从头开始并提示,不会把两个文件的时间戳混在一起。

### 按图统计:每张图到底赚了多少

收益按**区域码**归到具体的图,所以「哪张图值得刷」是用你自己的实测回答的,不是抄一份攻略。做这件事的关键是日志的 `MapDeforestation` 能对上地图表 —— 表以区域码为键,不是以名字为键,因为名字会重(七块地方都叫 `Precursor Tower`)且码**不能从名字推**(`MapSavanna` 叫 "Savannah"、`MapVaalFoundry` 叫 "Molten Vault")。区域码来自游戏数据(PoB2 的 `WorldAreas.lua`),不是命名约定。

表由 `scripts/build-maps.mjs` 生成,合并三个源:**PoB2 `WorldAreas.lua`**(区域码、`act=10` 判终局、Boss)+ **poe2wiki 地图表**(生态、布局描述原文)+ **POE2WAY**(跑图/回头路社区评分 1–4,以及社区手绘拓扑图)。表里不只有可刷图,还有传奇图、堡垒、首领场地、塔与藏身处,靠 `kind` 字段分类 —— **分类只用来筛选,不删行**,因为日志可能报出其中任何一个,join 必须成功。

诚实的部分和刷图统计一样明确:

- **约一半的图没有社区布局资料**(99 张可刷图里 50 张),一律显示「未标注」,不猜。
- 表外的新区域码**照常统计并标「表外」**,不会被丢掉 —— 这正是地图表被发现不完整的方式。`node scripts/verify-map-codes.mjs <Client.txt>` 读一份真实日志,列出每个区域码能不能对上表。
- 没有汇率覆盖的账目**计入「未计入」而不是当作 0**;「次数」就是样本量,只刷过一次的图不构成结论;同一张图刷在不同等级会混合平均,所以等级一并显示。

**不显示 div/hr 之类的收益数字。** 社区里没有可信来源:Maxroll 的机制强度榜只给字母档不给数字,唯一带数字的是个无人维护的单人仓库。本页给的是**你自己这次会话测出来的**数,并标注样本量。

## 异界天赋树

异界(Atlas)的终局天赋树:573 个节点、6 棵机制子树(裂隙 / 迷雾 / 祭祀 / 探险 / 深渊 / 神庙)加一棵主树。每个节点属于一棵子树,而子树就是玩法机制,所以「想刷哪个机制,就先点哪棵子树」是这一页要回答的问题。

**这一页把策略和玩法接起来的地方是生态。** 树里有 88 个节点的效果自己写着「在 X 区域」(`[Biome|Mountain] Areas ...`),而地图表的每个地区都带生态 —— 于是「哪些异界节点帮到你正在刷的图」有数据可依,不需要谁去编一份映射。

生态是两个页面共用的轴,来回都能走:

- **地图页**有生态筛选(每个生态带该类型下的地区数),地区详情里点生态 → 异界页按该生态高亮节点;
- **异界页**选了生态 → 列出该生态的地区(按社区跑图评分排)→ 一点回到地图页,筛选已经带过去。

三个城市地区(`Ezomyte`/`Faridun`/`Vaal City`)在树里是一句「City Areas」,所以两边都按 `atlasBiomeKey` 归一:点 `City` 会覆盖三座城,点具体某个城名只匹配它自己。

**图形是自绘的,不含游戏素材。** 角色天赋树的边框与图标来自 GGG 官方导出,而异界树没有对应的官方导出(`grindinggear/atlastree-export` 是 PoE1 的),公开数据导出里有节点坐标却没有贴图。所以这一页沿用剧情示意图的做法:形状与颜色承担全部含义,不假装是游戏截图。

数据由 `scripts/build-atlas.mjs` 从 `repoe-fork.github.io/poe2` 的 `passive_skill_trees/Atlas.json` 生成到 `packages/data/atlas.json`。该文件不带坐标 —— 节点位于所属 group 的 (x, y) 加上所在轨道的角度偏移 —— 所以构建脚本按游戏自己的约定把坐标烘进去(`sin` 定 x、`-cos` 定 y,即 0 号槽朝上、顺时针),渲染端只读坐标、不做三角函数。**连线也一起烘了**:584 条里有 290 条按导出记录的半径画成弧(同一环上的节点沿环弯曲,其余用该连线自己的 spline 半径,`INT_MAX` 表示直线),所以环读起来是环而不是一圈弦。几何正确性由子树聚集度验证:6 棵机制子树各自紧凑成簇并环绕主树,与异界树应有的形态一致。

规划器按游戏规则校验连通性:新节点必须能通过**已点节点**接到某个起点(子树入口),点一个远处的节点会自动补上通往它的最短路径,取消一个节点会连带取消后面挂着的 —— 因为游戏不会留下「有邻居但接不回起点」的孤立节点。

```bash
node scripts/build-atlas.mjs              # 用缓存
node scripts/build-atlas.mjs --refresh    # 重新抓数据
```

## 分享码

一个码带走整套配置:**服务器与赛季、天赋树、异界天赋、装备**(含技能组)。生成的是当前界面上的实时状态,导入则整体覆盖。

**分享码里没有登录凭证,这是格式层面保证的。** 国服的会话 Cookie(`POESESSID`)是登录,不是设置 —— 带上它等于把账号交出去。`ShareSnapshot` 里没有放它的字段,编码器只写自己声明的字段,所以一个码不可能顺手把它带出去(有单测专门验证这点:即使往快照里硬塞一个 `cnSession`,编出来的码里也找不到它)。

格式是自己的,不是 PoB 的扩展:PoB 码只带天赋和装备,异界方案此前没有任何东西能带走。开头是 `P2C1.`,后面是 zlib 压缩的 JSON 经 base64url 编码。**主页那个输入框两种码都收** —— 靠前缀区分,所以把自家码粘进 PoB 的框不会得到一句「解析失败」。

**节点列表做差值编码,这是码长的大头。** 节点 id 与异界 hash 是接近随机的六位数,写成十进制文本时 deflate 完全压不动 —— 一个点满的异界方案光这一项就占 3.4 KB JSON、deflate 后仍有 1.6 KB,占整个码的 62%。但列表是**有序**的,所以存差值:同样 573 个 hash 从 3388 字节变成 574 字节,deflate 后只剩 **16 字节**。效果是码长几乎不再随方案变满而增长:

| 方案规模 | 差值编码前 | 现在 |
| --- | --- | --- |
| 起步(20 异界 + 30 天赋 + 3 装备) | ~761 字符 | **587** |
| 中期(180 异界 + 90 天赋 + 8 装备) | ~1695 字符 | **672** |
| 点满(573 异界 + 123 天赋 + 12 装备) | ~3476 字符 | **748** |

编码器写打包形式,解码器两种都收(打包串,或旧的手写数字数组)。有一条回归测试锁住「点满的码不超过起步的两倍」,改回写十进制就会失败。

有一处**做不到**、也不假装能做到的:打包列表就是一串字节,所以截断如果正好落在字节边界上,会解出一个「更短但完全合法」的列表。防截断靠的是外面那层 deflate(压不开就报错),不是这个字段级检查。

**导入的码是不可信输入**,所以解码是校验而不是信任:不是自家的码、base64 非法、解压失败(多半是复制被截断)、版本号不认识 —— 这四种一律拒绝并说明原因;而仅仅类型不对的单个字段会被丢掉,不会因为一个字段就毁掉整次交接。节点列表会去重排序,所以顺序不属于状态的一部分,同一套配置永远编出同一个码。
